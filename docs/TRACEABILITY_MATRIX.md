## 2. Evaluation Criteria & Constraints Traceability

| ID | Constraint / Evaluation Area | Weight | Implementation Enforcement | Verification Method |
| :--- | :--- | :---: | :--- | :--- |
| **EVAL-01** | **Depth of Reasoning**<br>Non-obvious recommendations combining multiple environmental variables. | **30%** | Deterministic multi-variable relationship rules (e.g., `REL_SEMIARID_SOC_MONOCULTURE`) linking soil, rainfall, and cropping. | Benchmark test case (0.3% SOC, low rainfall, monoculture wheat): assert system produces intercropping/agroforestry coupling all 3 factors. |
| **EVAL-02** | **Scientific Grounding**<br>Claims backed by credible sources; accurate and explainable reasoning; no hallucinated numbers. | **25%** | `evidence_engine.py` validates citations against ChromaDB metadata and strips ungrounded quantitative claims. | Test suite verifies every recommendation has $\ge 1$ supporting peer-reviewed / FAO / IPCC citation and zero fabricated statistics. |
| **EVAL-03** | **Knowledge System Design**<br>RAG / vector DB / structured datasets with clean retrieval pipeline and document provenance. | **20%** | Local ChromaDB with `sentence-transformers/all-MiniLM-L6-v2`, provenance metadata headers, and transparent `/knowledge/query` API. | Test vector retrieval precision and verify document ingestion pipeline runs reliably on local machines. |
| **EVAL-04** | **Conversational Intelligence**<br>Context awareness, follow-up questioning, memory handling without request rejection. | **15%** | SQLite-backed `SessionManager` and `CompletenessEvaluator` detecting missing variables and explaining available context. | Multi-turn test scripts verify session memory accumulation and clarification gating without throwing errors or rejecting queries. |
| **EVAL-05** | **Output Clarity**<br>Structured, readable, and actionable responses. | **10%** | Strict Pydantic serialization with clean sectioning for actions, rationale, metrics, limitations, and reasoning trace. | Schema validation test ensures zero missing fields in JSON responses. |
| **CONST-01** | **No Generic LLM-Only Solutions** | — | System pipeline strictly enforces vector DB retrieval; rejects generation if knowledge layer is bypassed. | Unit test verifying reasoning pipeline calls retriever before generating responses. |
| **CONST-02** | **No Shallow Recommendations** | — | Recommender applies heuristics rejecting trivial keywords ("plant trees", "use sustainable methods"). | Test assertion on candidate recommendations ensuring technical specificity. |
| **CONST-03** | **Local Runnability & Simplicity (1-Day MVP)** | — | Zero cloud database dependencies; ChromaDB + SQLite run entirely in-memory or on local disk; single LLM provider with offline mock. | End-to-end execution of `pytest` and server launch on a clean local environment without Docker or Kubernetes. |
